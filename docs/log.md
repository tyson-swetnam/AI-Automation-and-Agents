## 2026-09-09

* **Update**: Moved the course onto current LangChain. LangChain 1.0 removed `AgentExecutor`, `create_react_agent`, `create_tool_calling_agent`, `initialize_agent`, `langchain.chains`, `langchain.memory`, `langchain.prompts` and `langchain.tools.Tool` from the `langchain` package with no deprecation shim, so those imports now fail with `AttributeError` or `ModuleNotFoundError` rather than a warning. The [Module 2 lab](modules/module-2/lab-notebook.md) was built entirely on `AgentExecutor` and installed LangChain unpinned, so it raised `ImportError` on its agent-building cell for every learner; it is rewritten on `create_agent`, which is what the module's own [foundational concepts](modules/module-2/foundational-concepts.md) page already documented. The [Module 2 resources](modules/module-2/resources.md) page carried two LangChain 0.x code samples with the same problem; both are rewritten. Its conceptual model of an agent runtime is framework-agnostic and is unchanged.
* **Update**: The lab's four-step shape, its student extension points, its self-checks and its log entries are preserved. What changed is how the reasoning loop is observed: `create_agent` returns a LangGraph graph rather than an `AgentExecutor`, so there is no `verbose=True` text trace printing `Thought:`, `Action:` and `Observation:`. A `show_trace` helper streams the graph instead and prints the same loop as structured data, and Step 1 now explains why the old labels are gone. Two sunset dependencies were dropped: `langchain-experimental`, which the lab imported but never installed, and `langchain-community`, whose DuckDuckGo wrapper now needs the renamed `ddgs` package. Both tools are defined in the notebook instead.
* **Update**: Pinned every notebook to the same current stack: LangChain 1.4.0, LangGraph 1.2.11 and LangSmith 0.12.4. Modules 3 and 5 had drifted to different LangChain patch versions, and Module 2 had no pin at all. Module 5's optional live-search cell installed the renamed `duckduckgo-search` package and never installed the library it imported, so it failed twice if a learner uncommented it. Its LangSmith setup now uses the documented `LANGSMITH_*` variables and clears the older `LANGCHAIN_*` ones first, because the older names take precedence and the value is matched against the literal lowercase string `true`; either trap turns tracing off silently and leaves an empty project with no error.
* **Update**: The four lab pages regained the `last_modified` date in their `sources` entry. `scripts/render_notebooks.py` was still looking for the notebook clone under `.cache/`, which `zensical build --clean` deletes because it is Zensical's own build cache; it now reads `.sources/` like the migration pipeline does, so it can read the notebooks' git history again.
