THREE KINDS OF AI

1 · PREDICTIVE MODEL

regression, classifiers

Learns a pattern from examples with known answers [8].

In: measurements. Out: a number or a label.

Who acts: a person, or code someone wrote.

On a robot or a vehicle

“Is that a pedestrian?” “How far will this battery go?”

2 · LANGUAGE MODEL

LLMs, chatbots

Learns the patterns of language from a vast amount of text [9].

In: a prompt in words. Out: text.

Who acts: the person reading it.

On a robot or a vehicle

“Explain this fault code.” “Draft the inspection report.”

3 · AI AGENT

a language model in a loop

A language model placed in a loop and given tools [10].

In: a goal. Out: actions, then a report.

Who acts: the agent itself, step after step.

On a robot or a vehicle

“Move tomorrow's drone survey to a dry time slot.”

Each wraps the one before: an agent is a language model in a loop, and the tools it calls are often predictive models.

AGENT

THE STRUCTURED PROGRAM THEOREM

SEQUENCE

Do this, then this, then this, in order. Like following a recipe.

read_sensor()
estimate_state()
send_command()

SELECTION

If this, do that; otherwise do something else. Like a traffic light.

if obstacle_ahead:
    brake()
else:
    cruise()

ITERATION

Keep doing this until something says stop. Like stirring until it thickens.

while not at_goal:
    step()

Böhm and Jacopini (1966) proved that these three are enough to write any program [12]. Dijkstra (1968) argued for using only these, so that a person can follow a program by reading it [13].

THE AGENT LOOP

1 · PERCEIVE

Read the goal and what has happened so far

2 · PLAN

Decide the next step, or decide to stop

3 · ACT

Use a tool to do it

4 · OBSERVE

Read what came back

5 · CONCLUDE

Report the answer

NOT DONE → LOOP AGAIN

DONE

Sequence

Everything so far is kept in order, and the agent rereads all of it on every lap.

Selection

On each lap the AI picks one tool by reading its description, or picks none.

Iteration

It keeps going until it decides it is finished. The only hard stop is a step limit a person sets.

FOR THE ENGINEERS · in LangChain the loop ends when the model returns no tool calls, and the step cap is recursion_limit [17]. Loop after AI Automation and Agents, Modules 1 and 2 [10].

WHO DECIDES WHAT HAPPENS NEXT

Building block

In ordinary software

In an AI agent

Sequence

A programmer wrote the steps, in order

The AI makes up the steps as it goes

Selection

A programmer wrote every if and else, and anyone can read and test them

The AI chooses, by reading descriptions written in plain English

Iteration

A programmer wrote the rule for when to stop

The AI decides when it is done, unless a step limit cuts it off

The three building blocks are still there. Their author is now an AI, deciding one step at a time, and that is where the questions about accountability, fairness and oversight come in.

FOUR WAYS AGENTS COORDINATE

1 · SUPERVISOR

Like a manager and a team: one agent splits the job up and assembles the result.

Fails when

The plan is wrong, or everything waits on the manager.

2 · PEER NETWORK

Like a drone swarm, or a committee with no chair: agents just trade messages.

Fails when

Group behaviour is hard to predict, and members can contradict each other.

3 · PIPELINE

Like an assembly line: each agent hands its work to the next.

Fails when

An early mistake travels through every later stage.

4 · MARKET

Like a dispatcher with a job board: agents claim or bid on tasks.

Fails when

The dispatcher is a single point of failure, and overhead is highest.

Teamwork among machines predates chatbots: Stone and Veloso (2000) surveyed it for robot teams [19]. Patterns after AI Automation and Agents, Module 4 [10].

FOR THE ENGINEERS · in practice: supervisor = LangGraph, peers = AutoGen, pipeline = MetaGPT or CrewAI, market = the contract net protocol.

WHY MULTI-AGENT SYSTEMS FAIL

SYSTEM DESIGN ISSUES

How the team was set up

Unclear roles, vague instructions, and no rule for when to stop.

INTER-AGENT MISALIGNMENT

Agents talking past each other

Not sharing what they know, ignoring each other, drifting off the task.

TASK VERIFICATION

Nobody checked the work

Stopping early, skipping checks, and accepting flawed results.

Where the loop comes in

Several of the failures are about the loop itself: repeating the same step, not knowing when to stop, or stopping too early.

From a study of failed runs of multi-agent AI systems: Cemri et al. [20], as summarized in AI Automation and Agents, Module 4 [10]

HALLUCINATION AS AN ENGINEERING PROBLEM

The objection

What is actually happening

The control

“It invents citations”

It never looked anything up

Make it search a real index first

“It makes up labels”

Any word is allowed, so nothing can be checked

Terms must come from an approved list (an ontology)

“It varies run to run”

Nothing fixes the shape of the answer

A form the answer must fit (a JSON schema), checked automatically

“I cannot audit it”

No record of what went in or what it did

A logbook of every step, so any run can be replayed

Google DeepMind GNoME proposed 380,000 crystals [24]; independent labs confirmed under 5%. Every output should be treated as a hypothesis until it is checked [11].

THE HUMAN GATE IS AN IF STATEMENT

The rule, in plain words

IF AN ACTION CANNOT BE UNDONE, STOP AND ASK A PERSON. OTHERWISE, CARRY ON.

while not done:
    action = plan(state)
    if action.irreversible:
        wait_for(human)
    state = observe(act(action))

Two questions before you automate

How much of the job can be written as rules? Score 1 to 5.

How bad, and how permanent, is a mistake? Score 1 to 5.

Rule-based but high-stakes does not rule out automation. It calls for checkpoints, testing, and approval gates before any step that cannot be undone.

Three design questions

Which actions need a gate? What must the reviewer see? What happens if they say no?

EU AI Act Article 14 [25] and the NIST AI RMF Govern function [26] both require defining where human authority is needed · AI Automation and Agents, Modules 1 and 5 [10]

FOR THE ENGINEERS · LangGraph, the OpenAI Agents SDK and CrewAI Flows treat approval gates as first-class; other frameworks leave you to build them.

WHAT COUNTS AS AN AGENT

“A computer system capable of autonomous action in an environment in order to meet its design objectives.” Wooldridge and Jennings (1995) [30].

AUTONOMY

Works without a person directing each step.

REACTIVITY

Notices when things change and responds in time. It is not following a fixed script.

PRO-ACTIVENESS

Works toward a goal on its own initiative, not only when prodded.

SOCIAL ABILITY

Works with people, and with other agents, through agreed rules.

A chatbot, a fixed script, a one-off lookup and a search engine each miss at least one of the four [10].

AGENTIC AI LOOPS · RAISE · FALL 2026

HOW AN AGENT PICKS A TOOL

Choosing from a menu

The AI never operates a tool itself. It names the tool it wants and fills in the details; the harness does the rest.

It chooses the way you pick from a menu: by reading each tool's description. A vague or misleading description leads to the wrong choice [10].

One standard plug

The Model Context Protocol (MCP) is a shared way to describe tools, so any tool can plug into any agent [34].

Tools can reach files, calendars, websites, even robots [7].

Anyone can publish one. A tool written by a stranger becomes part of your agent's decision making [32].

How well a tool is described matters more than anything else for whether the agent uses it correctly [10].

FOR THE ENGINEERS · a tool is a name, a description and a JSON schema for its arguments; the model emits a structured call and the harness executes it.

KNOWLEDGE AS A GUARDRAIL

Write it down

Agents forget everything between sessions. So have them write down what they learned, in plain files a person can read and the next agent can reuse [11].

Every page carries a label: what it is, where it came from, who checked it, and when it goes out of date. Google's Open Knowledge Format makes the label standard [39].

An approved vocabulary does the same for words: a term that is not on the list is rejected.

One page's label

type:        Setup Guide
title:     OpenAI ChatGPT
generated: by human:tswetnam
verified:    by human:tswetnam
status:     stable
stale_after: 2026-11-01

A machine may write “generated”. Only a person may write “verified” [7].

FOR THE ENGINEERS · this is how the course sites and the CARC docs are published: Markdown with OKF frontmatter, plus llms.txt for agents.
