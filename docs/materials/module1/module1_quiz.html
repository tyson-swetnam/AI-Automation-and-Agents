Instructor Answer Key & Rationale
# Type Answer LO Rationale
1MC Def.B1.1 The perception–reason–act loop with goal-directedness and autonomy from per-step instruction is the canonical AI-agent definition. Options A, C, D describe ML classifiers, chatbots, and rule-based bots respectively.
2MC Def.B1.1 Agent memory is the mechanism that stores past observations and retrieved context to inform reasoning — distinct from hardware RAM (C) or an API cache (D).
3MC Def.B1.1 ReAct interleaves chain-of-thought reasoning traces with tool calls, feeding results back into the model context. It is not RL (A), a front-end framework (C), or weight compression (D).
4MC Def.B1.2 RPA mimics human UI interactions via deterministic rules — no content understanding. Physical robots (A), ML pipelines (C), and fine-tuned LLMs (D) are distinct paradigms.
5MC Def.B1.2 Orchestration platforms execute human-authored DAGs or step graphs deterministically. The intelligence about what to do next resides in the developer-defined graph, not the platform itself.
6MC Def.C1.1 · 1.2 A multi-agent system coordinates specialized agents with distinct roles/tools. Model size (A), GPU nodes (B), and symbolic engines (D) do not define the paradigm.
7ScenarioC1.2 A time-triggered, hardcoded ETL script with no branching, no LLM, and no UI interaction is a scheduled/cron-based automation — the simplest paradigm on the autonomy spectrum.
8ScenarioB1.2 UI navigation through fixed menu paths to copy data without an API is the textbook RPA definition. The absence of reasoning or content understanding is the key discriminator.
9ScenarioC1.1 · 1.2 Goal-directed reasoning, adaptive tool invocation (web search, document retrieval), and autonomous multi-step synthesis without a predefined step script are the hallmarks of an AI agent.
10ScenarioD1.2 A fixed, developer-authored Airflow DAG is workflow orchestration. The pipeline never adapts its step sequence at runtime — a human must edit the DAG to change behavior.
11ScenarioB1.1 A coordinator model routing to specialist sub-agents (billing, support, refund) with distinct roles is a multi-agent system, not a single agent with tools (A) or an orchestration DAG (C).
12SequencingSee below1.1 Correct order: (1) Observe/perceive → (2) Retrieve goal & memory → (3) Reason & select action → (4) Execute action → (5) Receive feedback. The loop then re-enters from step 1.
13SequencingSee below1.2 Autonomy spectrum (low → high): (1) Cron script → (2) RPA → (3) Workflow orchestration → (4) Single LLM agent → (5) Autonomous multi-agent system.
14SequencingSee below1.2 Cost/complexity (low → high): (1) Zapier/no-code → (2) Cron script → (3) RPA attended bot → (4) Single LLM agent → (5) Autonomous multi-agent system.
