# AI Automation and Agents

Course site for **AI Automation and Agents**, a five-module course from the
[Center for Advanced Research Computing (CARC)](https://carc.unm.edu/) at the
University of New Mexico. The course moves beyond individual AI prompts into AI agents and
automated workflows: systems that take actions, use tools, manage files, and
complete multi-step tasks on a learner's behalf. Module 1 builds the
conceptual foundation (what agents are, the no-code / low-code / code-first
automation spectrum, hands-on work with Claude Desktop); Modules 2-4 introduce
LangChain, LangGraph, and CrewAI through guided Jupyter notebook labs on Google
Colab, covering reasoning architectures, tool integration, memory,
retrieval-augmented generation, and multi-agent coordination; Module 5 closes
with responsible agentic AI: production deployment, evaluation, observability,
security (OWASP Top 10 for LLM Applications), and governance grounded in the EU
AI Act and the NIST AI Risk Management Framework.

The site is built with [Zensical](https://zensical.org) and structured as an
[Open Knowledge Format (OKF) v0.2](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md)
knowledge bundle, so the content is first-class for both people and AI agents.
The implementation follows the
[UNM CARC documentation](https://github.com/UNM-CARC/docs) model.

**Live site:** <https://tyson-swetnam.github.io/AI-Automation-and-Agents/>

The site deploys from this fork (`tyson-swetnam/AI-Automation-and-Agents`).
The upstream course repository is
[UA-AI2S/AI-Automation-and-Agents](https://github.com/UA-AI2S/AI-Automation-and-Agents);
the course text is migrated from the
[AI-Automation-and-Agents-v2 wiki](https://github.com/UA-AI2S/AI-Automation-and-Agents-v2/wiki).

## Quick start

Python 3.12 is required (`.python-version`); the system Python on macOS is
too old. [`uv`](https://docs.astral.sh/uv/) creates the environment without
seeding `pip`, so install with `uv pip`:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements-dev.txt   # requirements.txt alone is enough to build
.venv/bin/zensical serve                    # live preview at http://localhost:8000
.venv/bin/zensical build --clean --strict   # static site in ./site
```

Before committing content changes:

```bash
.venv/bin/python scripts/okf_validate.py docs             # OKF conformance (CI-enforced)
.venv/bin/python scripts/site_lint.py docs zensical.toml  # course rules (CI-enforced)
.venv/bin/python scripts/gen_llms_txt.py                  # regenerate llms.txt indexes (CI fails on drift)
```

## Machine readability (OKF)

Every content page carries YAML frontmatter with:

- `type` (required by OKF) from a closed set: `Overview`, `Lesson`,
  `Reading Guide`, `Reading`, `Activity`, `Worksheet`, `Lab`, `Assessment`,
  `Resource List`, `Tutorial`, `Guide`, `Course Design`, `Policy`, `Reference`
- `title`, `description`, `tags` (a scope tag such as `course` or `module-N`,
  an audience tag `student-facing` or `instructor-facing`, then topics),
  plus `module` and `time_estimate` on module pages
- `generated: { by, at }` -- who or what produced the current content
  (`process:scripts/migrate_wiki.py`, `process:nbconvert`, or an agent id)
- `sources` -- provenance back to the wiki page, notebook, or primary text,
  with `author` and `last_modified` taken from the wiki's git history, and
  `authorship` (created / updated / contributors) from the wiki page footers
- `status` (`draft` | `stable` | `deprecated`), `stale_after` on pages tagged
  with a fast-moving tool (LangChain, LangGraph, CrewAI, Ollama, Colab, ...),
  and `superseded_by` on deprecated pages

Trust tiers follow OKF §5.3: a page with no `verified` key is **unverified**.
Migrated and agent-written pages are intentionally left unverified. When an
instructor reviews a page and confirms it, they add:

```yaml
verified: { by: "human:<netid>", at: "2026-XX-XXT00:00:00Z" }
```

The deployed site is directly consumable by AI agents:

- `/llms.txt` ([convention](https://llmstxt.org)) -- linked outline of every
  page with its description; `/llms-full.txt` -- the whole corpus, frontmatter
  included, in one file.
- **Markdown mirror**: any page URL + `index.md` returns that page's source
  with OKF frontmatter (e.g. `/modules/module-1/overview/index.md`).
- Rendered pages carry `<link rel="alternate" type="text/markdown">` and
  `okf:*` meta tags (`type`, `status`, `trust-tier`, `generated-at`,
  `generated-by`, `stale-after`, `superseded-by`).
- `robots.txt` advertises all of the above. `docs/about/ai-agents.md` is the
  human- and agent-readable guide to the surface; `AGENTS.md` guides coding
  agents working in this repository.

Regenerate the llms indexes after content changes (CI fails on drift), and
run the agent-surface step after every build:

```bash
.venv/bin/python scripts/gen_llms_txt.py
.venv/bin/zensical build --clean --strict && .venv/bin/python scripts/postbuild_agent_surface.py site
```

## The migration pipeline

`scripts/migrate_wiki.py` is a reproducible wiki-to-`docs/` conversion,
re-runnable while the content team is still editing the wiki. It reads a
clone of the v2 wiki (`.sources/wiki-v2`, or `WIKI_DIR`) pinned to the `WIKI_REF`
commit and the v2 repository clone (`.sources/repo-v2`, or `ASSETS_DIR`) for
images and notebooks, and asserts that the set of wiki files still matches its
`PAGES` table plus `DROPPED` set, so a new wiki page fails loudly instead of
silently going missing.

- One `PAGES` entry per output page holds the title, type, tags, status, and
  destination; exact-literal `PATCHES` fix wiki text (an unmatched patch is an
  error); `ALT_TEXT` has one entry per referenced image; `CALLOUT_MAP` and
  `ANCHOR_MAP` translate the wiki's one-column callout tables and GitHub
  heading slugs.
- Pages marked `frozen=True` were hand-curated after the first conversion and
  are never overwritten (landing page, `start-here/*`, `about/*`, the
  interactive-activity pages, `course-design/instructor-materials.md`, the
  portfolio tutorial, and the log).
- `--check` writes to a temporary directory and diffs against `docs/` (CI can
  run it to prove `docs/` matches the pinned wiki); `--only <page>` converts
  one page; `--notebooks` renders the learner notebooks into lab pages via
  `scripts/render_notebooks.py`. `scripts/optimize_images.py` copies exactly
  the referenced originals from `images/` into `docs/assets/images/`,
  downscaled to at most 1600 px wide.
- Section `index.md` files, `about/wiki-crosswalk.md`, and the image manifest
  are derived outputs; edit the script, not those files.

If the site ever moves to another repository, `site_url`, `repo_url`,
`edit_uri`, and the `REPO_SLUG` constant change together, every page flips to
`frozen`, and `docs/` becomes the source of truth.

## Deployment

Pushing to `main` runs `.github/workflows/docs.yml`: OKF validation, the
course lint, the llms.txt drift check, a strict Zensical build, the
agent-surface post-processing, post-build assertions, and a deploy to GitHub
Pages at <https://tyson-swetnam.github.io/AI-Automation-and-Agents/>. Pull
requests get the validation and build jobs without the deploy; a monthly
scheduled run surfaces `stale_after` warnings. The workflow enables Pages
automatically (`configure-pages` with `enablement: true`); if the first
deploy fails on permissions, set Settings > Pages > Source to "GitHub
Actions" once and re-run.
